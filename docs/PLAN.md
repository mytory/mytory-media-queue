# Mytory YT-DLP 실행 계획

## 목표

Windows x64, macOS Universal, Linux x64에서 설치해 사용하는 Tauri 2 데스크톱 다운로드 앱을 만든다. 사용자는 여러 URL을 같은 **Download Queue**에 넣고, 실행 중에도 추가하며, 기본 MP4 호환 출력으로 내려받는다. **Managed Update**는 yt-dlp와 `yt-dlp-ejs`만 자동 갱신한다.

## 확정 범위

- UI/런타임: Tauri 2, React/TypeScript, Rust.
- 번들: Deno, FFmpeg, FFprobe, `yt-dlp-ejs`; yt-dlp는 최초 설치본도 제공한다.
- 지원: Windows x64, macOS Apple Silicon·Intel Universal, Linux x64.
- 입력: 다중 URL, 재생목록 확장, 실행 중 대기열 추가.
- 출력: URL 추가 시 목적지를 선택하며 기본값은 OS 다운로드 폴더. MP4 호환 우선이 기본값이고, 최고 품질 영상·원본 품질 오디오·MP3 320kbps를 제공한다.
- 부가 파일: 썸네일은 기본 저장. 자막은 사용자가 켠 경우 제공 자막을 한국어→영어 우선으로 별도 `.vtt`에 저장한다. 자동 생성 자막, 영상 내 삽입, 설명 파일은 제외한다.
- 대기열: Download Concurrency의 기본값은 3개이며 사용자는 1~5개로 설정한다. 종료 시 확인하고 트레이로 숨기지 않는다. 중단 작업은 다음 실행에서 재개한다.
- 기록: 대기·진행·실패와 최근 90일의 완료 이력을 로컬에 저장한다. 이력 삭제는 파일을 지우지 않는다.
- 로그인: 브라우저 프로필 또는 `cookies.txt`를 고급 옵션으로 선택한다. 쿠키는 저장·표시·로그하지 않는다.
- 오류: 네트워크 오류만 최대 3회 자동 재시도하며, 사용자는 재시도·취소·결과 폴더 열기·정제된 로그 복사를 할 수 있다.
- 배포: 서명/공증 없는 플랫폼별 설치 파일을 비공개 배포한다. 앱 자체는 자동 갱신하지 않는다.
- 개인정보: 원격 분석(telemetry)과 자동 오류 전송은 없다.

## 설계

### 경계

- React UI는 사용자 입력, 대기열 표시, 설정, 확인 대화상자만 담당한다.
- Rust의 `DownloadService`가 영속 대기열, 동시성 제한, 재시도, 종료/재개, 이력 정리를 소유한다.
- Rust의 `DownloaderRunner`는 형식화된 요청만 받아 yt-dlp 인수를 구성하고, stdout/stderr 진행 이벤트를 작업 상태로 변환한다. UI는 임의 yt-dlp 인수를 전달할 수 없다.
- Rust의 `ToolManager`는 번들 도구 위치, 현재/이전 Managed Update 세트, 해시 검증, 원자 교체와 롤백을 소유한다.
- 설정·대기열·이력은 앱 데이터 디렉터리의 로컬 SQLite에 저장한다. `Cookie Source`의 실제 값과 원시 로그는 저장하지 않는다.

### 도구 배치와 실행

1. Tauri의 플랫폼별 sidecar 번들로 Deno·FFmpeg·FFprobe·초기 yt-dlp를 포함한다. Tauri는 target triple 접미사가 붙은 sidecar를 요구하므로 각 대상별 도구를 준비한다.
2. 최초 실행 시 관리 대상 도구를 앱 데이터 디렉터리에 초기화한다. 실행은 Rust가 절대 경로와 고정 인수 목록으로 수행하며 셸 문자열을 만들지 않는다.
3. `yt-dlp-ejs`와 yt-dlp는 같은 버전 세트로 보관한다. Deno와 FFmpeg 계열은 앱 릴리스에서만 바뀐다.
4. 업데이트는 하루 한 번 시작 시 확인하거나 수동 확인한다. 공식 안정 릴리스와 체크섬의 출처·호환 세트는 구현 전 스파이크로 검증한다.
5. 새 파일은 임시 디렉터리에 다운로드하고 해시·실행 가능 여부를 확인한다. 활성 작업이 없을 때만 현재 세트를 교체하고, 실패 시 이전 세트를 유지한다.

## TDD 전략

모든 TDD 동작 테스트는 **실제 yt-dlp나 외부 사이트를 실행하지 않는다.** 대신 독립 실행 파일인 **Downloader Simulator**를 사용한다. Simulator는 실제 프로세스와 동일한 인수/표준출력 경계를 가지되, 시나리오에 따라 진행률·성공·일시 네트워크 실패·권한 실패·중단을 결정적으로 출력한다. 내부 메서드 mock은 사용하지 않는다.

실제 번들 바이너리는 릴리스 전 별도 패키징 점검에서 해시와 `--version`만 확인한다. 네트워크를 통한 실제 다운로드는 TDD/CI의 필수 경로가 아니다.

### 수직 슬라이스 순서

1. **핵심 경로:** 다중 URL과 목적지를 등록하고 Simulator가 첫 작업을 진행하는 중 새 URL을 추가한다. 앱 재시작 뒤 중단 작업이 대기열에서 재개되는지 검증한다.
2. **스케줄러:** 동시성 1·3·5 제한, FIFO 시작, 취소, 종료 확인, 재개를 검증한다.
3. **출력 요청 변환:** 네 Output Preset, 자막/썸네일 규칙, 재생목록 폴더와 파일명 충돌 규칙이 안전한 고정 인수로 변환되는지 검증한다.
4. **실패 복구:** Simulator의 일시 실패가 정확히 세 번 재시도되고, 권한·삭제·디스크 오류는 즉시 사용자 조치 상태가 되는지 검증한다.
5. **보안/개인정보:** Cookie Source가 프로세스 실행에만 전달되고 DB·UI 이벤트·진단 로그에 기록되지 않는지 검증한다.
6. **Managed Update:** 로컬 테스트 HTTP 서버와 고정 아티팩트/체크섬으로 다운로드, 검증, 지연 적용, 원자 교체, 롤백을 검증한다.

각 항목은 `RED(공개 서비스 행동 테스트) → GREEN(최소 구현) → 리팩터` 순으로 완료한다.

## 단계별 작업

### 0. 스파이크 및 기반

- Tauri 2/React/Rust 프로젝트와 SQLite 마이그레이션을 생성한다.
- 세 플랫폼 target triple용 도구 목록과 획득/해시 매니페스트 형식을 확정한다.
- `DownloaderRunner` 공개 계약과 Downloader Simulator를 먼저 만든다.
- yt-dlp/`yt-dlp-ejs` 공식 안정 배포물, 체크섬, 호환 세트의 재현 가능한 획득 절차를 검증한다. 이 검증이 끝나기 전에는 자동 업데이트를 구현하지 않는다.

### 1. 대기열 수직 슬라이스

- Download Queue·작업 상태·SQLite 영속성을 구현한다.
- 다중 URL, 목적지 선택, MP4 기본값, 진행 중 추가, 종료 확인과 시작 시 재개를 구현한다.
- 1번 TDD 시나리오를 통과시킨다.

### 2. 스케줄링과 사용자 제어

- 1~5 동시성, 기본값 3, 취소·재시도·진행률·속도·ETA·결과 폴더 열기를 구현한다.
- 이력 90일 정리와 로컬 로그 정제를 구현한다.
- 2~4번 TDD 시나리오를 통과시킨다.

### 3. 다운로드 옵션과 인증 경계

- 네 Output Preset, 재생목록 폴더, 동명 충돌, 썸네일 및 선택형 자막을 구현한다.
- 브라우저/프로필 및 `cookies.txt` 선택 UI를 고급 옵션에 추가한다.
- 쿠키 비저장·비로그 보장을 테스트한다.

### 4. Managed Update

- ToolManager의 스테이징·체크섬 검증·원자 교체·이전 세트 보존을 구현한다.
- 업데이트 상태와 수동 확인 UI를 추가한다.
- 활성 Download Queue가 있는 동안에는 적용을 미루고, 실패는 기존 세트를 유지한다.

### 5. 패키징·배포

- Windows 설치 파일, macOS Universal DMG, Linux AppImage을 대상 OS에서 빌드한다.
- sidecar 권한을 최소화하고 앱이 허용 목록의 도구만 실행하도록 설정한다.
- 설치/제거, 최초 실행, OS 다운로드 폴더, 업데이트 실패, Gatekeeper/SmartScreen 안내를 각 플랫폼에서 수동 점검한다.
- 비공개 배포용 설치 안내와 도구별 라이선스/고지 파일을 포함한다. 비공개 배포도 재배포 조건을 면제하지 않는다.

## 완료 조건

- 세 지원 플랫폼에서 설치 후 별도 의존성 설치 없이 핵심 대기열 흐름이 동작한다.
- 실제 URL을 사용하지 않는 결정적 TDD 스위트가 위 여섯 행동군을 검증한다.
- Downloader Simulator 실패 시나리오에서 쿠키나 원시 인증 정보가 저장/로그되지 않는다.
- Managed Update 실패가 실행 가능한 기존 yt-dlp/`yt-dlp-ejs` 세트를 손상시키지 않는다.
- 배포 문서가 무서명 앱의 OS별 최초 실행 절차와 앱 업데이트가 수동임을 명시한다.

## 알려진 위험 및 후속 작업

- 사이트별 추출 규칙과 로그인/anti-bot 정책은 자주 바뀐다. Managed Update의 출처·체크섬 검증 스파이크가 주요 위험 제거 항목이다.
- 무서명 Windows/macOS 배포는 신뢰 경고를 만든다. 배포 인원이 늘면 코드 서명과 macOS 공증을 재검토한다.
- Linux 배포판·데스크톱 환경 차이와 브라우저 키링/Flatpak 프로필은 별도 호환성 매트릭스로 관리한다.
- Windows ARM·Linux ARM, 고급 포맷 문자열, 자동 생성 자막/내장 자막, 텔레메트리는 현재 범위 밖이다.
